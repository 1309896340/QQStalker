## MODIFIED Requirements

### Requirement: 大模型响应文件缓存

系统 SHALL 支持把成功的大模型响应持久化到输出目录下的 `.llm-cache/` 目录：每个缓存条目为一个 JSON 文件，SHALL 记录响应文本与完成原因；缓存键 SHALL 由阶段标签、模型标识、请求参数与完整请求内容的哈希确定性构成。请求在发起任何网络调用之前 SHALL 先查缓存，命中时 SHALL 直接返回缓存结果且不产生网络流量。

缓存写入 SHALL 与下游校验联动：响应在获得后先经过该阶段的输出校验，校验通过方可写入缓存；校验失败的响应 MUST NOT 写入缓存，且响应写入时尚未完成校验的实现 MUST 在校验失败时清除该条目，使其在本次运行与后续运行中均视为未命中。请求以异常结束（网络失败、内容审查拦截、流式空响应等）时 MUST NOT 写入缓存。

缓存 MUST 随输出目录隔离：不同输出目录的缓存互不混用。更换模型、更换影响响应的请求参数或修改 prompt 都 MUST 产生不同的缓存键。系统 SHALL 提供命令行开关在本次运行中完全跳过缓存读写。并发线程同时写缓存 MUST NOT 产生损坏的缓存文件。

#### Scenario: 命中缓存不重复请求

- **WHEN** 同一份 prompt 与参数在先前运行中已成功获得响应，本次运行再次发起同一请求
- **THEN** 系统直接返回缓存的响应文本与完成原因，不产生任何网络请求，下游校验与渲染行为与网络请求一致

#### Scenario: 失败请求重跑时自动重试

- **WHEN** 某次请求以异常结束（如内容审查拦截或流式空响应），用户重跑任务
- **THEN** 该请求不命中缓存并重新发起，其余已成功的请求全部命中缓存，不重复计费

#### Scenario: 开关跳过缓存

- **WHEN** 用户以 `--no-cache` 运行
- **THEN** 本次运行不读取也不写入缓存，行为与无缓存实现一致

#### Scenario: 键随模型与参数隔离

- **WHEN** 同一 prompt 分别以不同模型或不同请求参数发起
- **THEN** 两者使用不同的缓存键，互不命中

#### Scenario: 并发写入不损坏缓存

- **WHEN** 多个并发请求线程同时写入不同缓存条目
- **THEN** 每个缓存文件完整可解析，不出现半个文件或交叉内容

#### Scenario: 校验失败的响应不持久化

- **WHEN** 模型响应已写入缓存，但下游 JSON 校验判定其非法（如 JSON 解析失败或结构不符合阶段约定）
- **THEN** 系统清除该缓存条目，本次运行与后续重跑中该请求均视为缓存未命中并重新发起请求，MUST NOT 反复命中同一条投毒缓存

#### Scenario: 校验通过的响应正常复用

- **WHEN** 某响应通过了其阶段的输出校验并被写入缓存，本次运行再次发起同一请求
- **THEN** 缓存命中且响应直接复用，不因校验联动被清除
