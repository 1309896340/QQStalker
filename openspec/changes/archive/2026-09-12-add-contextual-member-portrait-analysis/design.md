## Context

当前分析器使用一个 Markdown 正则将消息按成员聚合为完整文本块，再按成员块字符数分批。这样保留了每人的全部内容，却让成员之间的时序信息在请求组装时丢失。`generate_portrait.py` 也直接调用同一分析函数，因此任何新增配置必须在两个入口一致读取。动机见 [proposal.md](proposal.md)。

## Goals / Non-Goals

**Goals:**

- 在不改变导出格式的前提下，建立可重用、可测试的时序消息表示。
- 以确定性规则在总输入预算内为每位成员提供有互动价值的上下文。
- 让模型能使用直接可见的互动线索，同时保持最终 Markdown 和 HTML 展示契约不变。

**Non-Goals:**

- 不引入主题模型、额外 LLM 预筛选或时间窗口模式。
- 不将聊天证据、新字段或原文片段呈现在最终报告中。
- 不调整数据库、导出器、HTML 渲染器、实时服务或 LLM HTTP 协议。

## Decisions

### 使用时序消息记录作为单一输入事实来源

分析器将从现有导出块中构造不可变的消息记录，包含递增序号、解析出的时间、显示名、正文和原始渲染文本。成员聚合、活跃度统计、窗口构建和提示词序列化都从该记录派生；服务账号与系统消息在此阶段排除。这样窗口、统计与最终请求共享同一套顺序和成员归属。

备选方案是继续传递 `member -> 完整 Markdown 块`，并在每个成员分组内反查全记录。该方案需要重复解析、难以按序号去重，且会让预算计算依赖脆弱的文本拼接，因此不采用。

### 用信号优先、时间分层的确定性中心选择

先从有正文的目标成员消息中识别显式互动线索：`@`、引用/回复结构、点名或明确提问。此类消息优先成为窗口中心；剩余名额在整个时间轴上分层选择，避免仅收集最早或最密集的一段。不会尝试从关键词或 LLM 推导“不同话题”，时间多样性是可测试的最佳努力替代。

备选方案包括按长度或情绪权重排序、关键词聚类以及另发 LLM 请求。它们分别偏向长消息、引入语言特定不确定性，或增加成本和隐私暴露，均不采用。

### 按消息条数截窗、合并并一次序列化

每个中心使用前后消息数配置（默认各 3 条）在已过滤的普通成员时序记录上截取。窗口按序号合并并去重后，按原始顺序输出；若一条目标代表发言同时位于上下文中，序列化时只保留一次，并用中心标记表明它是代表性发言。每条上下文消息都带有时间和发言者。

不采用时间跨度窗口：聊天稀疏时会不受控地扩大输入，聊天密集时又可能缺少足够的往来。

### 两层预算而非按成员完整装箱

新的组装器先计算提示词固定开销和每个成员的基础资料，然后从每成员 `12000` 字符候选上下文中按轮转加入窗口，直到达到 `LLM_MAX_INPUT_CHARACTERS`。在加入额外窗口前，先为每名同批成员保留统计、代表性发言和一个可用窗口；若配置小到无法组成最小请求，则在调用模型前报出清晰错误。字符长度沿用现有 Python 字符计数语义。

单条候选消息无法完整加入时，保留其消息头并截断正文，加上明确的截断标记。提示词会声明截断内容不能支持超出可见范围的推断。这样保留会话定位和请求完成性，而不突破硬上限。

备选方案是动态缩小批次或按活跃度给更多预算。前者改变现有调度和请求数量，后者会让低活跃成员更容易缺少互动依据；二者均不采用。

### 上下文只提高模型判断，不扩展报告展示

提示词将把同批名单与有标记的代表性上下文分开说明。它允许显式指向或语义明确的连续问答支持互动描述，也允许对象位于批次名单外；同时明确禁止从纯粹相邻、同批出现或截断文本推断关系。输出继续使用当前画像字段和既有“代表性观点”转述要求，不要求添加互动字段、证据标签或原文摘录。

备选方案是新增“互动依据”字段并输出短引。该方案更可审计，但会扩大报告中的聊天内容暴露范围，已排除。

### 两个入口统一读取配置

新增配置常量和验证函数保留在分析器模块，独立 CLI 与 `generate_portrait.py` 都通过同一环境读取逻辑向分析流程传值。窗口前后值使用非负整数验证并额外拒绝双零；窗口数与字符数继续使用正整数验证。原有筛选、批次缺失补偿、群像速览和精选语录调用顺序不变。

## Risks / Trade-offs

- [解析依赖导出 Markdown 格式] → 复用现有块匹配约束，为带时间、多人往来和排除账号的最小脱敏样本编写解析测试，并沿用现有格式不匹配错误。
- [字符数不等于模型 token 数] → 将现有字符上限继续作为明确硬预算，并给固定提示词开销预留空间；不承诺 token 精确计量。
- [语义明确的连续问答仍需要模型判断] → 提示词只将其作为可用证据之一，并显式排除单纯相邻或无指向的消息。
- [截断可能隐藏消息结尾] → 加入截断标记并禁止模型基于不可见内容推断；完整消息优先于截断候选加入。
- [上下文可能增加请求量或成本] → 每成员和每请求双重预算、窗口上限及轮转分配限制增长。

## Migration Plan

1. 发布包含默认环境变量的版本；未设置新变量时使用保守默认值，现有 `.env` 无需迁移。
2. 先运行单元测试和静态检查，再用脱敏的小型导出验证输入大小、成员覆盖和 HTML 输出。
3. 如需回退，移除新环境变量并恢复此前分析器版本；没有数据库或导出数据迁移。
