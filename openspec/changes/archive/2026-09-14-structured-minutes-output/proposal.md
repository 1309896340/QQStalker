## Why

纪要以"单个自然段、200~300 字"生成，五名参与者的观点被压进一段，模型只能用逗号把整段串成一个长句，过渡词机械（"X认为…Y提出…Z表示…"），阅读体验差；本地 300 字确定性截断在整段无句读时原地硬切，产出以单字"结"结尾的残句，且兜底路径不做参与者覆盖校验，导致名单中的成员从正文消失。纪要面向群员发布、用于自我审视，语言质量直接决定这份产物的可信度。

## What Changes

- 最终纪要从"单个自然段"改为结构化输出：总览句（议题核心与分歧所在）+ 按参与者分条的观点归纳（每人一条，高度凝练概括）+ 仅在真实形成共识时的一句话收束；总长上限从 300 字放宽到 400 字，要求对每人观点做高度凝练的概括。
- 最终阶段响应启用 JSON 硬校验（结构、member 逐字等于名单署名、覆盖、长度、句末标点、禁套话），校验失败携带反馈自动重写；全部重写失败后先抢救部分有效的结构化结果（丢弃非法条目），无法抢救时按既有分层降级（拼接分段纪要 / 本地发言摘录）。
- 修复 `truncate_at_sentence` 无句读硬切：任何兜底截断文本必须以完整句或省略号收尾，禁止词中间断头。
- 分段（partial）纪要保持自然段形态与 300 字上限不变；仅最终归并/撰写阶段结构化。
- 生成指令增补：中立转述、不加评价、不嘲讽；禁用"本次围绕……展开讨论"式开头与"未达成最终结论……交换了看法"式空泛收尾；观点凝练概括。
- 渲染侧：正文按"总览 + 分条 + 收束"排版；支持样式的 HTML/PNG 中，正文内超过 8 字的成员姓名截断显示（悬停可见全名），署名中的括号备注（如"（本人回应）"）剥离渲染为独立徽标；Markdown 与主要参与者名单行保持完整姓名。
- 数据结构：`DiscussionTopic.minutes` 从单一字符串改为结构化纪要对象（含降级整段文本的兜底形态）；纪要不落库，无数据迁移。
- **BREAKING**：`DiscussionTopic.minutes` 字段类型变更（模块内数据结构，不落库、无外部消费方，影响面限于分析产物构建与渲染）。

## Capabilities

### New Capabilities

（无）

### Modified Capabilities

- `portrait-discussion-minutes`：最终纪要的形态（自然段 → 总览+分条+收束）、长度上限（300 → 400 字）、结构化 JSON 校验与抢救降级、兜底截断禁止词中间断头、正文姓名截断显示与括号备注徽标、降级呈现条款的相应调整。

## Impact

- `src/qqstalker_cli/discussion_analysis.py`：纪要数据结构、最终阶段指令与校验、抢救与降级、截断修复、`to_markdown`。
- `src/qqstalker_cli/analyze_transcript.py`：请求层 `json_output` 透传（最终纪要请求启用 `response_format=json_object`）、渲染 HTML 内联 JS 与 CSS（分条排版、姓名截断、备注徽标）。
- `tests/test_analyze_transcript.py`：新增结构化校验/抢救/降级用例，调整涉及最终纪要自然段形态的既有用例。
- 通用 JSON 校验规格（`llm-json-response-validation`）为阶段无关契约，纪要最终阶段纳入后无需修改该规格。
