## Context

现有分析链路在 analyze_all_members 中从导出 Markdown 解析时序消息、生成成员画像，再生成群像速览和语录精选，最后由 build_analysis_document 组装报告。现有时序解析已保留导出顺序并排除了 Q群管家和系统消息，但其有效文字判定只服务成员画像窗口，不足以覆盖媒体占位、撤回消息和专题计数的边界。

报告 HTML 先将模型 Markdown 转换并用 Bleach 清洗，再通过浏览器脚本把 H3 标题归类为用户卡或语录卡。受此约束，讨论议题不能只依赖普通 H3 结构，也不能让模型 Markdown 携带图表脚本。PNG 由 Playwright 在 file URL 页面截图；现有资源等待逻辑没有图表就绪信号。动机和用户可见范围见 proposal.md。

## Goals / Non-Goals

**Goals:**

- 为全量有效聊天消息建立可复算的议题归属、热度和时序摘要数据。
- 在任意记录长度下保持时间顺序和单次 LLM 输入上限。
- 将专题以独立语义区域安全地放入 HTML 与 PNG，并让原始 Markdown 有等价可读表示。
- 使专题失败局部降级，且无效配置在两个入口启动时尽早失败。

**Non-Goals:**

- 不改变成员画像的字段、筛选、上下文窗口或缺失成员补偿行为。
- 不修改数据库、消息导出格式、实时同步服务或 LLM HTTP 协议。
- 不承诺主题分类绝对客观，也不把模型推断、完整原文或单条消息引用作为报告证据字段。
- 不构建离线交互式图表包、实时更新看板或按个人拆分的热度图。

## Decisions

### 将专题数据与成员画像 Markdown 分离

新增内部专题结果模型，至少保留稳定议题标识、展示标题、按原始序号排列的消息归属、时间范围、主要参与者、纪要、讨论度和时间桶序列。build_analysis_document 接收专题的可读 Markdown 片段及其结构化图表数据；render_html 从受信任的参数而非模型文本注入图表容器与数据。

这样可以让热度图、标题、时间范围和段落共享同一事实来源，也避免讨论标题被现有 H3 卡片化逻辑误判为成员或语录。备选方案是只解析模型返回的 Markdown 标题和段落来反推图表数据；它无法稳定校验消息覆盖和热度，且会把不可信输出扩展为渲染控制面，因此不采用。

### 为专题使用独立的有效文字过滤和稳定消息身份

专题从 contextual_analysis.parse_messages 的时序结果派生，但添加仅供专题使用的过滤器。过滤器去除空白、导出器的无文本/撤回/图片与表情占位、纯 Unicode 表情，并保留真实文字及其附带的媒体标记。每条保留消息使用原始序号、时间、成员和清理后的正文作为稳定身份；相同时间戳不重新排序。

不复用成员上下文的 has_textual_content：它的目标是选择窗口中心，且对导出占位中的 Markdown 符号不够严格。独立过滤能避免改变已在工作树中的成员画像行为，并使讨论度的分母可测试。

### 使用分段分类、层级归并和选题后纪要的有界链路

先将有效消息序列化为带序号、时间和成员的记录，按原始顺序切成不超过 LLM_MAX_INPUT_CHARACTERS 的专题请求；提示词固定开销必须预留，单条异常长消息保留头信息并标记截断。每段请求返回可验证的结构化分类：本地议题摘要和每条消息唯一的主议题归属。

随后将各段摘要和本地归属按相同预算递归合并，统一跨段同义议题。合并结果必须能映射回所有参与统计的消息；验证失败时可做一次有界修复请求，仍无法修复即将专题视为可恢复失败。确定的归属表在本地计算消息数、首次出现顺序、参与者、时间范围及自适应时间桶，按热度取 LLM_MAX_DISCUSSION_TOPICS 个议题。

仅对选中的议题再按其消息的原始顺序分段总结和归并为最终段落。提示词要求每句列出发言者、观点、行动和有证据时的立场对象，并禁止凭相邻消息推断认同或反对。这避免把整份记录直接发送给一个请求，也让热度计算不依赖模型文本中的模糊数量。

备选方案是像当前语录精选一样把完整 transcript 直接交给单次请求，或只按关键词做本地聚类。前者在长记录中突破预算且无法可靠生成全局热度；后者对同义表达和中文口语不稳，均不采用。

### 采用确定性自适应分桶和堆叠面积序列

时间桶选择器根据记录跨度在小时、天、周、月之间选择粒度，并设置有限的目标点数以保持宽度约束下可读。对每个选中议题及每个桶以归属消息数求和，空桶补零；图例、纪要标题和颜色由稳定议题标识共同派生。图表只显示最终保留的前 k 个议题，未显示的低热度议题不合并进其他颜色。

选择堆叠面积图是为了同时阅读总讨论量与各主题的相对贡献。备选的重叠面积图容易遮挡，固定按日粒度会让短会话缺细节或让多年记录过密，因此不采用。

### 用固定版本 CDN 的 ECharts 安全渲染并提供同源降级

HTML 模板注入固定版本的 ECharts CDN 脚本、显式高度的图表容器和经 JSON 安全转义的序列数据。模型 Markdown 仍走 Bleach 清洗；专题标题与段落由受信任的专题 DOM 包装逻辑先处理，再让已有脚本处理成员和语录，避免 H3 归类冲突。原始 Markdown 中保留同源的热度数据降级表示，供不执行脚本的阅读路径使用。

图表初始化禁用动画，成功绘制后设置明确就绪标记，加载失败时显示可读降级内容。render_html_png 在测量文档高度和截图前等待该标记或失败标记；专题容器固定高度并使用 break-inside avoid，减少分片中截断图表的风险。图表数据只在本地页面中消费；CDN 请求不上传聊天数据。

备选方案是让 LLM 输出 script/canvas、在 Markdown 中嵌入不受信任 HTML，或使用未固定版本的远程库。它们分别会被清洗器移除、带来执行注入风险或破坏可复现渲染，因此不采用。

### 配置验证与专题故障采用不同的失败边界

LLM_MAX_DISCUSSION_TOPICS 在 load_dotenv 之后立即通过既有正整数校验读取；独立 CLI 在读取输入前、一体化入口在导出前完成该操作，以满足启动即失败。专题中 LLM、归并或图表资源的运行期错误则被局部捕获，转换为专题位置的短说明，让主报告保留既有结果。

备选方案是对无效配置也生成部分报告，或让任一专题错误中断全部管线。前者使配置错误难以及时发现，后者违背用户对降级的要求，因此不采用。

## Risks / Trade-offs

- [语义归类受模型输出质量影响] → 约束为可校验的消息归属，使用固定的脱敏夹具、归属完整性验证和一次有界修复；统计与排序始终从验证后的本地数据计算。
- [超长记录带来更多模型调用和成本] → 每次请求受现有字符上限约束，局部摘要先压缩再归并，并只为最终入选议题生成完整纪要。
- [CDN 不可用或版本变更] → 固定经审核的版本、显示同源数据降级内容，并在渲染测试中覆盖失败标记。
- [聊天数据或模型文本导致脚本注入] → 保持模型 Markdown 清洗，图表只接收验证后的结构化数据并进行 JSON 上下文转义。
- [图表异步绘制导致 PNG 截图过早] → 禁用动画，使用就绪或失败标记并由 Playwright 显式等待。
- [现有 H3 视觉增强误包专题标题] → 先隔离讨论纪要 DOM 区域，再仅对对应区域应用成员卡和语录卡增强。

## Migration Plan

1. 发布时在 .env.example 中加入 LLM_MAX_DISCUSSION_TOPICS=5；旧 .env 未设置该变量时自动使用默认值，无数据库或导出数据迁移。
2. 先运行专题的单元与渲染测试、静态检查和语法编译，再使用包含同主题跨段、媒体占位和 CDN 失败模拟的脱敏导出进行端到端验证。
3. 如需回退，移除专题调用和 HTML 模板资源即可恢复原有报告顺序；此前生成的 HTML/PNG 保持可读，且没有需要回滚的持久化数据。
