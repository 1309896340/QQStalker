## Why

现有画像报告虽然提供群像速览、个人画像与语录精选，但无法从完整聊天记录中还原群内主要议题的时间脉络、参与者立场和讨论热度。用户需要一个位于个人画像之前的专题，让高频议题、讨论演变及其在整个记录中的分布可以被一并阅读。

该能力应在超长记录中保持可用，并以可配置的上限控制报告篇幅；同时必须避免把无明确证据的相邻消息误写成赞同、反对或人际关系。

## What Changes

- 从完整、按导出顺序排列的有效真人文字消息中识别语义议题，合并跨时间段反复出现的同一议题，并保持同一时间戳消息的原始顺序。
- 新增 `LLM_MAX_DISCUSSION_TOPICS` 环境变量，默认值为 `5`；报告按有效消息数计算讨论热度并最多展示热度最高的 `k` 个议题，议题不足时展示实际数量，超出的低热度议题不进入专题。未配置使用默认值，空值、非整数或非正整数在两个入口启动后立即报出清晰错误。
- 为每条参与统计的有效消息分配唯一主议题，以消息数同时驱动议题排序和时间热度；排除服务/系统消息、空内容、撤回/媒体占位与纯表情内容，保留带真实文字的媒体说明。
- 在超出单次输入预算的记录中采用有界的分段提炼、跨段议题归并和最终纪要生成，确保所有专题请求遵守输入预算，并以结构化的消息归类结果支撑可复算的统计与图表数据。
- 在“群像速览”之后、“用户画像列表”之前新增“讨论纪要”专题。专题顶部展示按时间自适应分桶的堆叠面积图，横轴为时间、纵轴为讨论热度、议题固定分色并提供图例；每个保留议题展示标题、时间范围、主要参与者及按时间推进的一段讨论纪要。
- 约束纪要中的每个句子归因到发言者并说明其观点和评价/行动；仅在聊天记录有直接证据时描述认同或否认对象，不能用无指向的相邻消息虚构立场关系。
- 以固定版本 CDN 引入 ECharts，由受信任的 HTML 模板注入经过安全序列化的图表数据，而不是让 LLM Markdown 携带脚本。HTML/PNG 渲染等待图表就绪、避免动画与跨分片截断，并在 CDN 或专题生成失败时保留主报告和简短降级说明。
- 补充配置、分段归并、热度统计、报告排序、纪要约束、HTML/PNG 图表与降级路径的测试。

## Capabilities

### New Capabilities

- `portrait-discussion-minutes`: 基于完整时序聊天记录生成可配置数量的主要议题纪要及其时间热度图，并以安全、可降级的方式嵌入用户画像报告。

### Modified Capabilities

- 无。

## Impact

- 受影响代码：`src/qqstalker_cli/analyze_transcript.py`、`src/qqstalker_cli/contextual_analysis.py`、`src/qqstalker_cli/generate_portrait.py`、`src/qqstalker_cli/render_html_png.py`。
- 受影响配置：`.env.example` 增加 `LLM_MAX_DISCUSSION_TOPICS=5`；现有 LLM 输入预算继续作为新增专题请求的硬上限。
- 受影响呈现：生成的 HTML 和 PNG 将包含 ECharts CDN 脚本、讨论纪要的专属 DOM/CSS 和离线/失败降级内容；个人画像卡和语录精选的语义边界保持不变。
- 受影响测试：`tests/test_analyze_transcript.py`、`tests/test_generate_portrait.py`，并新增或扩展 PNG 渲染就绪与图表布局的覆盖。
- 不修改数据库结构、消息导出格式、实时服务或 LLM 提供商 HTTP 协议。
