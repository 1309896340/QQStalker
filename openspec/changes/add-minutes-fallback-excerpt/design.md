## Context

`write_topic_minutes` 捕获 `RuntimeError` 后把该议题纪要写为固定占位句"该议题的纪要生成失败，未能概括讨论内容"。议题消息集合（`topic_messages`）与参与者计数在该函数内现成可用，摘录所需数据无需额外获取。

## Goals / Non-Goals

**Goals:**

- 失败议题保留可读的信息量：谁、在什么时间、说了什么代表性内容。
- 摘录生成确定性、零额外请求、零失败面。

**Non-Goals:**

- 不做本地文本摘要算法（抽取式选句已足够；摘要质量仍由 LLM 路径负责）。
- 不改变分段失败（消息不计入议题）与整体失败（专题不可用）的既有处理。
- 不新增"减半输入重试"等 LLM 层替代方案（留待后续变更）。

## Decisions

- **参与者均衡抽取。** 按参与者消息数从多到少轮转，每人先取一条最长有效消息，再按名额补取第二条，总条数上限 8 条；最终按时间排序输出。均衡的意义：避免摘录被刷屏者的消息淹没，与"主要参与者"列表相互印证。
- **消息过滤与截断。** 复用 `discussion_text` 的过滤口径（去占位/表情后的有效文本）；每条截断到 60 字（硬截断加省略号，不追求句子边界——摘录本就是片段）。全部消息都被过滤掉时退回一句"纪要生成失败（原因）且无可用文字消息"。
- **标注格式。** 首行为"模型纪要生成失败（原因摘要），以下为主要发言摘录："；失败原因取错误消息首句并截断，避免泄露敏感细节；每条格式 `[HH:MM] 成员：内容`。
- **失败原因随条目呈现。** 占位句升级为摘录的同时，把失败原因（此前只在控制台警告）写进议题条目，读者可直接判断失败性质。

## Risks / Trade-offs

- [摘录不是概括，读者需要自行阅读原文] → 明确标注摘录性质；这是失败降级路径，信息保真优先于可读性。
- [错误消息可能包含敏感细节] → 只取首句并限制长度；与现有控制台警告的暴露范围一致，不额外扩大。

## Migration Plan

单次代码变更，无数据迁移；重新生成报告即生效。回滚即还原该次提交。
